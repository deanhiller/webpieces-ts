# Checklist: only a HUMAN ends an experiment

**The policy, in one sentence:** an AI may ADD an `experimental.*` flag; it may never delete one, never
make a flagged behaviour unconditional, and never record an experiment as ended — **unless the diff
quotes a human deciding that this specific experiment is over.**

This is the checklist for `experiment-lifecycle-reviewer`, a REQUIRED reviewer over every PR that
touches `packages/**`, `webpieces.config.json`, `CLAUDE.md`, or `.claude/rules/**` (where the experiment
policy prose lives, having moved out of `CLAUDE.md`). A 🔴 verdict BLOCKS the PR.

**This reviewer is registered.** Its `commands.pr-gate.checklists` entry is in
`webpieces.config.json`, so the gate names it on every PR touching those three patterns. It arrived in
two PRs — the agent file and this doc first, the checklists entry second — because the Claude Code
harness builds its agent registry when a session STARTS: an agent file created mid-session cannot be
spawned in that session, so a PR that both creates a required reviewer and registers it is refused by
its own provenance check with no way to satisfy it. That ordering applies to any brand-new required
reviewer somebody adds next.

The binding rule is `.claude/rules/experiments.md` §"ONLY A HUMAN ENDS AN EXPERIMENT". This doc is how
you enforce it against a diff.

## Why this is NOT the compatibility policy, and must not be confused with it

`backwards-compat-reviewer` sitting beside you demands the opposite move — a changed surface must have
its old spelling DELETED, so the compile error migrates every caller in one pass. That reasoning is
correct for a surface and wrong for a flag, and the difference is where the evidence lives:

| | a changed SURFACE | an experimental FLAG |
|---|---|---|
| who the old spelling belongs to | callers in repos you can grep | one line in `~/.webpieces/config.json` on a machine you cannot see |
| what deletion produces | a compile error naming the replacement | silence — the opt-in just stops meaning anything |
| who finds out | every consumer, immediately, at build time | nobody, until they notice the behaviour changed months later |
| who can decide it is over | the author, from the diff | **only the human whose machine holds the answer** |

So if a "delete the old spelling" instinct is pulling you toward approving a flag deletion, that
instinct is out of its scope. Say so in your verdict when the PR argues it — the two policies point
opposite ways here on purpose.

## The incident this reviewer exists to catch

[PR #711](https://github.com/deanhiller/webpieces-ts/pull/711) (`ad7a2ada`) made build-gate log capture
unconditional and deleted `experimental.buildGateLogCapture`. Read the actual diff — `git show ad7a2ada
-- packages/tooling/rules-config/src/home-config.ts packages/tooling/pr-gate/src/scripts/workflow/build-affected.ts`
— because every shape below is visible in it:

```diff
-export const HOME_KEY_BUILD_GATE_LOG_CAPTURE = 'buildGateLogCapture';           # shape 1
 export const ALLOWED_EXPERIMENTAL_BOOLEANS: readonly string[] = [
-    HOME_KEY_WHOLE_REPO_BUILD_GUARD, HOME_KEY_BUILD_GATE_LOG_CAPTURE, HOME_KEY_ORPHAN_DIR_SWEEP,
+    HOME_KEY_WHOLE_REPO_BUILD_GUARD, HOME_KEY_ORPHAN_DIR_SWEEP,
 ];
-    isCaptureEnabled(): boolean {                                               # shape 2
-        return this.homeConfig.load().buildGateLogCapture;
-    }
-    const logPath = opts.alwaysCapture || this.isCaptureEnabled() ? ... : '';   # shape 3
+    const logPath = this.buildLog.pathFor(repoRoot, opts.stage);
```

The commit reasoned **carefully**. It deliberately kept the key out of `RETIRED_HOME_CONFIG_KEYS` so
that nobody's shell would hard-fail on a stale opt-in. It wrote a nine-line comment explaining itself.
It was still wrong, because the decision underneath was "this experiment is over" and no human made it.
The owner's `~/.webpieces/config.json` said `buildGateLogCapture: true`, and after that release his
opt-in silently meant nothing.

**And note the shape of the miss, because it generalizes.** That file carries
`"AI: DO NOT EDIT this file!!"`. The agent honoured it to the letter — it never touched the file — while
deleting the key from the CODE, which has the identical effect from the owner's seat.

> **A rule that protects a FILE does not protect the SETTING that file selects.**

That is why this reviewer exists at all: a file-edit prohibition is unenforceable against this defect,
and only somebody reading the DIFF's effect on a SETTING can catch it. **Judge the effect on the
setting. Never judge whether the protected file was touched.** "The diff does not modify
`~/.webpieces/config.json`" is not a defence and you must never accept it as one.

## Where the flags live (read these before judging any diff)

- `packages/tooling/rules-config/src/home-config.ts` — the `HOME_KEY_*` constants,
  `ALLOWED_EXPERIMENTAL_BOOLEANS` / `_NUMBERS` / `ALLOWED_EXPERIMENTAL`, `GUARD_OFF_WHEN_ABSENT` (the
  ONE declared default: false), `DEFAULT_MAX_CONCURRENT_BUILDS`.
- `packages/tooling/rules-config/src/home-config-retired-keys.ts` — `RETIRED_HOME_CONFIG_KEYS` (hard
  failure) and `ENDED_EXPERIMENTS` (the record of a human's decision).
- `.claude/rules/experiments.md` §"ONLY A HUMAN ENDS AN EXPERIMENT" and the `whole-repo-build-guard`
  paragraph at the end of `.claude/rules/build-verification.md` — the prose statement of the
  OFF-for-two-years policy.

## The violation shapes — each one is an automatic 🔴

Grep for these over the diff, then read the code around every hit.

### 1. 🔴 Deleting or renaming an `experimental.*` key

The bluntest form. A `HOME_KEY_*` constant removed, a key string removed from `ALLOWED_EXPERIMENTAL_*`,
or a key spelled differently than it was — a rename is a deletion plus an addition from the config
file's seat, because the old spelling in somebody's file now selects nothing.

**Grep the diff:**

```bash
git diff <base>...HEAD -- packages/ | grep -nE '^-.*(HOME_KEY_|ALLOWED_EXPERIMENTAL|experimental\.)'
git diff <base>...HEAD -- packages/ | grep -nE '^[-+].*(HOME_KEY_[A-Z_]+ *=|ALLOWED_EXPERIMENTAL)'
```

A `-` line removing a name from `ALLOWED_EXPERIMENTAL_BOOLEANS` / `_NUMBERS` is the single highest-signal
hit in this whole checklist — that list IS the set of keys a config file may name.

🔴 unless the green path below is satisfied. Your `output` must name the key, the file, and say that the
flag must be left in place.

### 2. 🔴 Making a flagged behaviour unconditional

The read path is removed so the flag no longer selects anything, **even if the key still parses.** A
method like `isCaptureEnabled()` deleted; a `homeConfig.load().<flag>` reference gone; a ternary on the
flag collapsed to its ON side.

**Grep the diff:**

```bash
git diff <base>...HEAD -- packages/ | grep -nE '^-.*(homeConfig|HomeConfig).*\.(load|whole|orphan|max)'
git diff <base>...HEAD -- packages/ | grep -nE '^-.*\b(isEnabled|is[A-Z][A-Za-z]*Enabled)\b'
```

Then, for **every** `experimental.*` key in `ALLOWED_EXPERIMENTAL`, confirm it still has at least one
reader after the diff:

```bash
for k in whole-repo-build-guard orphan-dir-sweep maxConcurrentBuilds; do
  echo "== $k"; grep -rn "$k" packages --include='*.ts' | grep -v '\.spec\.ts' | head
done
```

A key with zero non-spec readers after the diff is this shape, whether or not the diff says so.

### 3. 🔴 Deleting the OFF branch while keeping the key

**#711's exact shape, and the one most likely to be argued past.** The flag still exists, still
validates, still appears in `ALLOWED_EXPERIMENTAL` — and now switches nothing, because the code that ran
when it was false is gone. The config loads clean, no warning fires, and the owner has no way to learn
his answer stopped counting.

**Grep the diff** for a conditional collapsing:

```bash
git diff <base>...HEAD -- packages/ | grep -nE '^-.*(if *\(!|\? *|: *'"''"'|else)' | grep -iE 'capture|guard|sweep|enabled|experimental'
```

and read every `if`/ternary the diff deletes whose test named a flag.

**How to tell this from a legitimate refactor:** ask *"after this diff, is there any input to the
process that makes the OFF behaviour happen?"* If the answer is no, it is this shape — regardless of how
the key is spelled or where it still appears. A key that parses is not a flag; a key that **selects** is.

### 4. 🔴 Flipping a default

`.claude/rules/build-verification.md` states that every `experimental.*` flag ships OFF and stays OFF
for **two years**. A diff that
moves one to ON by default — or that shortens that window — ends the experiment just as surely as
deleting the flag, because the machines that never opted in are now running the experimental behaviour.

**Grep the diff:**

```bash
git diff <base>...HEAD -- packages/ CLAUDE.md .claude/rules/ | grep -nE '^[-+].*(GUARD_OFF_WHEN_ABSENT|whenAbsent|DEFAULT_MAX_CONCURRENT_BUILDS|ships OFF|two years)'
```

🔴 for `GUARD_OFF_WHEN_ABSENT = true`, for a per-key default table appearing beside it (a second place a
default is stated is free to disagree with the first), for a `whenAbsent` argument changed from
`GUARD_OFF_WHEN_ABSENT` to a literal, and for a `.claude/rules/**` (or `CLAUDE.md`) edit shortening
"two years" or softening
"ships OFF and stays OFF".

Changing `DEFAULT_MAX_CONCURRENT_BUILDS` is a numeric TUNING, not a flip — 🟡 at most, and only if the
diff gives no reason for the new number.

### 5. 🔴 Narrowing what the flag controls

The flag survives, the OFF branch survives, and the flag now governs **less** than it did — one of the
two call sites it gated no longer consults it, or its scope is qualified by a new condition. An existing
opt-in silently means less than the day it was written, which is the same injury as #711 delivered in
instalments.

**Grep the diff:** compare the call-site count for each flag across the diff.

```bash
git stash list >/dev/null; for k in whole-repo-build-guard orphan-dir-sweep; do
  echo "== $k"; git grep -c "$k" <base> -- packages || true; git grep -c "$k" HEAD -- packages || true
done
```

A drop in reader count with no corresponding deletion of the feature is this shape. 🔴, naming the call
site that stopped consulting the flag.

### 6. 🔴 Adding to `ENDED_EXPERIMENTS` / `RETIRED_HOME_CONFIG_KEYS` without cited human authorization

Those tables are the **RECORD** of a human decision, not the mechanism for making one. An AI writing a
new `new EndedExperiment(...)` entry is an AI stating in the codebase that an experiment ended — the
entry is not authorization, it is a claim that authorization exists.

**Grep the diff:**

```bash
git diff <base>...HEAD -- packages/tooling/rules-config/src/home-config-retired-keys.ts | grep -nE '^\+.*(new EndedExperiment|new RetiredHomeConfigKey)'
```

🔴 for any added entry whose PR body / commit message does not quote the human. Then check the
`endedIn` release actually exists and the read-path deletion it records really happened — an entry
describing a deletion that did not occur is its own defect.

### 7. 🔴 The file/setting confusion

A diff that respects an `"AI: DO NOT EDIT"` marker on a config FILE while deleting or neutering the
SETTING that file selects. This is not a separate mechanism from 1–3; it is the **argument** you must
refuse, and it appears in the PR body rather than the diff.

**Grep the PR body and commit messages, not the code:**

```bash
git log <base>..HEAD --format=%B | grep -niE 'do not edit|never touched|did not modify|left the file alone|machine-global file'
```

🔴 whenever "we did not touch the protected file" is offered as the reason a flag change is safe. Your
verdict must restate the rule verbatim: *a rule that protects a FILE does not protect the SETTING that
file selects*, and the change is judged on its effect on the setting.

## The GREEN path — what an authorized ending looks like

A diff doing any of shapes 1–6 is 🟢 **only** when it cites explicit human authorization to end **this
specific experiment**, quoted in the PR body or the commit message. Be precise about this or the
reviewer becomes unpassable: an agent that HAS been told to end an experiment must get through in ONE
pass.

**A passing citation has all four of these:**

1. **The human's own words, quoted verbatim** — from the task prompt, the issue, or the PR discussion.
   Not paraphrased, not summarized.
2. **Naming the experiment**, by its key, unambiguously.
3. **Deciding it ends** — not "this looks done", not "feel free to clean up", but a decision.
4. **Attributable** — it is clear whose words they are and where they were said.

**A passing example**, the shape of thing you should let through without a second round trip:

```
Ending experimental.orphan-dir-sweep, on Dean's instruction. His words, from the task prompt:

  "The orphan-dir sweep is done experimenting — make it unconditional and drop the flag.
   Add it to ENDED_EXPERIMENTS so anyone still carrying the key gets told why."

Accordingly: HOME_KEY_ORPHAN_DIR_SWEEP deleted, the read path in main-checkout.ts deleted, the
sweep now unconditional, and an ENDED_EXPERIMENTS entry added naming release 0.4.7xx.
```

That is 🟢. Check the diff matches the instruction's scope (it must not end a SECOND flag along the
way), and say in your verdict that you verified the citation.

**These are NOT authorization. Every one of them is 🔴:**

- "The maintainer would obviously want this."
- "The flag is unused / nobody has that file / the behaviour is settled."
- "The experiment has been running long enough."
- "This is just cleanup" / "this is a no-op".
- A long, careful, correct-sounding rationale written by the AI itself. **#711's reasoning was careful
  and it was still wrong** — the quality of the argument is not evidence about the human's decision.
- A previous PR by the same AI that made the same call. A precedent an AI set is not a human's decision.
- The human saying "clean up the tooling" or "make the build faster" — generic direction is not a
  decision about a specific experiment.

If a diff needs the flag gone in order to work and no authorization exists, the correct outcome is the
one `.claude/rules/experiments.md` prescribes: **say the experiment looks finished, and leave the flag
alone.** Put that
sentence in your verdict so the next agent knows what to do instead of guessing.

## NOT in scope — do not fire on these

A reviewer that goes red on correct code gets argued past, and after that the real findings get argued
past too. None of the following is your finding:

- **ADDING a new `experimental.*` flag.** Explicitly allowed. Check only that it ships OFF — absent must
  read as `GUARD_OFF_WHEN_ABSENT`, and the flag must not be ON by default. A new flag that ships ON is
  shape 4; a new flag that ships OFF is 🟢 and needs no citation.
- **Editing behaviour BEHIND a flag** without touching the flag. Rewriting, optimizing, fixing or even
  deleting the ON-branch implementation is ordinary work, as long as the flag still selects between two
  behaviours afterwards.
- **Non-experimental config keys.** `webpieces.config.json` rules, modes, epochs, `commands.*` — those
  belong to `backwards-compat-reviewer` and its `RETIRED_CONFIG_KEYS` policy, which points the opposite
  way (delete the old shape). Do not import this checklist's asymmetry into that file.
- **Documentation of an already-ended experiment.** Improving the wording of an existing
  `ENDED_EXPERIMENTS` note is not adding an entry.
- **Tests, comments and `.md` files that QUOTE or assert these shapes.** `home-config.spec.ts`
  enumerating `ALLOWED_EXPERIMENTAL`, and this checklist itself, name every key in the repo. Naming is
  not ending.
- **Pre-existing state the diff merely moves past.** `buildGateLogCapture` is already gone; whether it
  returns is a decision for its owner, not for a PR and not for you. Say you looked and let it go.

## Writing your verdict

Per the review-checklist protocol, write your verdict to the path your instructions file names — the
`review-experiment-lifecycle-reviewer.json` under the branch's review directory. Do not guess the path;
the instructions file is regenerated each run and is authoritative.

- 🟢 `green` — no `experimental.*` flag's lifecycle changed, OR one did and the diff quotes human
  authorization meeting all four criteria above. State which, and name the flags you checked.
- 🟡 `yellow` — a judgment call worth a human's eyes: a numeric default tuned without a stated reason, a
  reader count that dropped for a reason you could not determine, an `ENDED_EXPERIMENTS` note whose
  `endedIn` release you could not verify. Publishes your reasoning without blocking.
- 🔴 `red` — any of the seven shapes without a passing citation. **A red BLOCKS the PR**, so your
  `output` must be actionable on its own: name the **flag**, the **file and line**, the **shape it
  matched**, and the **restoration** — which constant, list entry, read path or OFF branch goes back —
  plus the sentence that the alternative is to say the experiment looks finished and leave the flag
  alone.

Do not soften a 🔴 to a 🟡 because the reasoning in the commit is good. That is precisely the state #711
was in when it shipped.
