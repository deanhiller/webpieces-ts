# Experiments: ONLY A HUMAN ENDS ONE

Moved verbatim out of `CLAUDE.md`. Read this when your diff touches an `experimental.*` flag, its read
path, its default, or the policy prose about experiments -- and before you conclude that an experiment
looks finished.

### ONLY A HUMAN ENDS AN EXPERIMENT

**RULE: an AI may ADD an `experimental.*` flag. It may NEVER delete one, and it may never make a
flagged behaviour unconditional.** No matter how settled the behaviour looks, how long the flag has
existed, or how good the reasoning is. Say the experiment looks finished, and leave the flag alone.

This is not symmetric with the deletion policy above, and the difference is the whole point. Deleting a
changed *surface* is right because the compile error migrates every caller in one pass. Deleting a
*flag* deletes somebody's answer to a question nobody asked them again — and the evidence for whether
the experiment is over lives on their machine, which an agent cannot see.

Written from a live incident. PR #711 deleted `buildGateLogCapture` and made build-log capture
unconditional. The commit reasoned carefully — it deliberately kept the key OUT of
`RETIRED_HOME_CONFIG_KEYS` so nobody's shell would hard-fail — but the decision underneath was "this
experiment is over", and no human made it. The owner's `~/.webpieces/config.json` said
`buildGateLogCapture: true`, and after that release his opt-in silently meant nothing.

Note the shape of the miss, because it generalizes: that file carries `"AI: DO NOT EDIT this file!!"`,
and the agent honoured it to the letter — it never touched the file — while deleting the key from the
CODE, which has the identical effect from the owner's seat. **A rule that protects a FILE does not
protect the SETTING that file selects.**

**Enforcement:** `experiment-lifecycle-reviewer` (`.claude/agents/experiment-lifecycle-reviewer.md`) is
REGISTERED in `commands.pr-gate.checklists` and REQUIRED, over `packages/**`, `webpieces.config.json`
and `.claude/rules/**` (this file) — the three places an experiment's ending shows up: the flags and
their read paths, the config, and the "ships OFF and stays OFF for two years" policy prose. A red verdict blocks the PR, and
its `output` names the flag, the file, and the restoration that should have happened instead. It is a
REVIEWER and not a rule for the reason the paragraph above gives: a rule can only see a FILE, and this defect is visible only in
a diff's effect on a SETTING. `.claude/review/experiment-lifecycle.md` lists the seven shapes it rejects
— deleting or renaming a flag, making a flagged behaviour unconditional, deleting the OFF branch while
keeping the key, flipping a default to ON, narrowing what a flag controls, writing an
`ENDED_EXPERIMENTS` entry, and offering "we never touched the protected file" as a defence — and, just
as importantly, the GREEN path: a diff that ends an experiment passes when it QUOTES the human deciding
that this specific experiment ends. Your own reasoning is never that quote, however good it is.

`~/.webpieces/config.json` has no comment syntax, so `_doc` and `_aiDoc` are understood documentation
keys there: any string, accepted at the top level and inside `experimental`, ignored by the loader,
never advertised in a "did you mean" hint. Use `_aiDoc` to leave an instruction aimed at the next
agent. They must hold a string — `_doc: true` is somebody reaching for a setting and landing on the one
key name the loader promises to ignore, so it is rejected rather than warned.
